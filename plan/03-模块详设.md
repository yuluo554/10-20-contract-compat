# 03 · 模块详设

> 每个模块给：接口 / 数据结构 / 处理顺序 / 失败路径 / 测试点。口径类枚举一律引用 `data/README.md` §四。

## 0. 模块与文件对应

| 模块 | 文件 | 里程碑 |
|---|---|---|
| 规范 JSON 与 digest | `src/contractcompat/canonical.py` | M0 骨架（仅签名）/ M5 完成 |
| 三解析器 → IR | `src/contractcompat/parsers/{proto,avro,jsonschema}.py` + `ir.py` | M1（IR 形态 golden 的必要条件；M2 补解析器单测与双跑断言） |
| 方向性判定核 | `src/contractcompat/policy.py` | M3 |
| 破例规则库 | `src/contractcompat/rules.py` + `rules/rule-table.json` | M4 |
| 归因 + 修复 | `src/contractcompat/blast.py` | M5 |
| 报告 | `src/contractcompat/report.py` | M5（`--emit-ir` 的 IR 出口已在 M1 落地） |
| CLI / 退出码 | `src/contractcompat/cli.py` | M0 骨架 / M5 完成 |

**M0 只落"可运行的空壳 + 参数面 + 退出码契约"**：解析器/判定/规则/归因/报告的函数体返回
`NotImplementedError`，但 **CLI 的参数解析、错误分类、`--version`、布局门、exit code 2/3 的路径必须真跑**。
任何一处"返回 0 的空壳"都不允许（项目纪律：`return 0` 的空壳会被测试误认为成功）。

**M1 翻转了什么**：三解析器的映射体与 CLI 的 `--emit-ir` 出口已落地（`policy.diff`/`rules.evaluate`/
`blast.attribute` 仍是 `NotImplementedError` → 普通 `compat <old> <new>` 仍退出 3，**未实现不返回 0** 这条没破）。

## 1. canonical.py（规范序列化 / digest）

```python
def dumps(obj) -> str:            # sort_keys=True, ensure_ascii=False, indent=2, 结尾 LF
def loads(text) -> dict:          # 严格 JSON；失败抛 CanonicalError
def digest(obj) -> str:           # sha256(dumps(obj).encode("utf-8")) 十六进制小写
def verify_report(obj, expected_digest) -> list[dict]  # 返回差异定位列表，空表示一致
```

- 全仓**唯一**允许调用 `json.dumps` 的地方（AST/文本守门）。
- **key 序**：`sort_keys=True` 是兜底，真正的键序由报告构造时显式插入决定；两者一致才保证跨实现可比。
- `verify_report` **先比内容再比 digest**：先算 `digest` 会把"哪一处被改了"盖掉。
- 差异定位输出 `[{"json_path": "findings[3].severity", "expected": ..., "actual": ...}]`。

**失败路径**：非 JSON 文本 → `CanonicalError`（CLI 映射 2）。非 dict 顶层 → 同上。

**测试点**：`test_canonical.py` —— 中文不转义、键序稳定、同对象双跑字节一致、改一字节 digest 变、
`verify_report` 定位到叶子路径（含数组下标）、结尾恰好一个 LF。

## 2. ir.py（ContractIR）

```python
@dataclass(frozen=True)
class Field: ...
@dataclass(frozen=True)
class ContractIR:
    format: str
    name: str
    fields: tuple[Field, ...]
    reserved_numbers: tuple[int, ...]
    reserved_names: tuple[str, ...]
    ir_unsupported: tuple[Unsupported, ...]
def sort_fields(fields) -> tuple[Field, ...]   # 规范序，缺失 number 的排后面
def to_json(ir) -> dict
```

- **不读时钟、不读路径、不读环境**。
- `sort_fields` 的键：有号为 `(0, number, "", name)`，无号为 `(1, 0, json_pointer, name)` ——
  **避免比较 `None`**（Py3 `None < int` 抛 `TypeError`）。
- 同一文件两次解析 → `to_json` 字节一致（测试断言，不是"看起来一样"）。

**失败路径**：解析器构造 IR 时发现结构非法 → `SchemaParseError`（→ 退出码 2）；
发现结构合法但不可表达 → 进 `ir_unsupported`，**不抛错**（除非 `--require-complete-ir`）。

## 3. parsers/proto.py

输入：`FileDescriptorSet`（`.pb`，由 `protoc --descriptor_set_out` 产出）或 `.proto` 文本。

```python
def parse(path, *, require_complete_ir=False, protoc_runner=None) -> ContractIR   # parsers/__init__.py
def parse_descriptor_set(path, require_complete_ir=False) -> ContractIR           # parsers/proto.py
```

- `.proto` 文本 → **不解析**，也**不代跑** `protoc`（工具只读两个文件、零子进程）；
  直接 `CapabilityError`（退出码 3），并给出 `protoc --descriptor_set_out=...` 的用法提示，**不降级猜测**。
  （`protoc_runner` 仅保留为测试注入口，默认路径不调用它。）
- 解析 `FieldDescriptorProto` 的 `name/number/label/type/default_value/json_name`、`oneof_index`、
  `EnumDescriptorProto` 的 `name/number`、`DescriptorProto.reserved_range/reserved_name`。
- **跨 message 字段号复用（R5 的核心增量）**：同一文件内 `message A` 与 `message B` 使用同一号
  → 记录在差异项的 `evidence` 里（需要 new 侧自洽检查，属于 M4 的规则求值面）。
- `google.protobuf` 缺失 → `CapabilityError`，错误文本给安装提示。

**测试点**：`test_parser_proto.py` —— 描述符解析出字段号/reserved/oneof/enum；两份描述符双跑 IR 一致；
缺 protobuf → 退出码 3（用 `builtins.__import__` 桩，不依赖本机装没装）；`.proto` 文本且无 protoc →
退出码 3；非法 `.pb` → 退出码 2。

## 4. parsers/avro.py

输入 `.avsc`（纯 JSON）：**首期只把顶层 `record` / `error` 映射成 IR**；顶层 `enum` / `fixed` / `map`
等其它形态 → `SchemaParseError`（退出码 2），不硬凑成"空 IR"。
字段级支持 `enum`（内联或按名引用）、`union`、`array`、`map`、`logicalType`。

- `fields[*].name/type/default/aliases` → `Field`；**`number` 与 `json_pointer` 都留 `None`**——
  Avro 按字段名解析，稳定路径就是字段名（`data/README.md` §4.3："A: 字段名"）。
  ⚠️ 早期本文档写过"`number` 取数组下标"，与 §4.3 冲突；口径以 §4.3 为准，实现按 §4.3。
- `enum.symbols` → `enum_values`，`number` 取符号下标（Avro 二进制编码里 enum 用下标，这是真编号）。
- 无 `default` 且不含 `null` 分支 → `cardinality=required`；含 `null` → `nullable`（R3 的证据形态）。
- `name` 变化且新侧声明了 `aliases` 含旧名 → **不判 remove+add**（R1 的 Avro 证据形态）。
- union 成员 → 压成 `union(a,b,...)`，**保留声明顺序**；`oneof_membership` 留空；`N/A` 语义见 §4.3。

**测试点**：`test_parser_avro.py` —— 字段名/默认值/别名/枚举下标七项齐；union 加类型不判破（反例）；
改名带 alias 不判破（反例）；非法 JSON → 退出码 2。

## 5. parsers/jsonschema.py

输入 `.json`（draft-07 / 2020-12 子集）。

- `properties` → `Field`；`required` → `cardinality=required`；`type` → `type`；
  `enum` → `enum_values`（`number` 为 `null`）；`oneOf`/`anyOf` → `oneof_membership`。
- `$ref` **仅在可解析范围内展开**（同文件 `#/definitions/...` 或 `#/$defs/...`，无环）。
- **不可表达构造必须落 `ir_unsupported`**：`patternProperties`、`if/then/else`、递归 `$ref`、
  `dependentSchemas`、`propertyNames`。带 `json_pointer` 与 `reason`。
- `additionalProperties: false` 进 `ir` 的元信息（归因要用"未知属性容忍度"）。

**测试点**：`test_parser_jsonschema.py` —— properties/required/enum/oneOf 七项齐；
`patternProperties` 用例产出**非空** `ir_unsupported`（不是空 IR）；`--require-complete-ir` 时退出码 3；
递归 `$ref` 不栈溢出（必须有环检测）。

## 6. policy.py

```python
def diff(old: ContractIR, new: ContractIR) -> DiffResult
def judge(diff, policy: str, history=()) -> Verdict
def mapping_table() -> list[dict]   # buf 四档映射（data/README §4.2 的代码侧副本）
```

- `diff` 只产出**事实**：新增/删除/类型变/基数变/默认值变/enum 收窄/oneof 移动/字段号复用/与 reserved 冲突。
  每项固定键：`kind / format / field / number / stable_path / direction / old / new / detail / reason`。
  **方向是事实、policy 是选择**：`diff` 不接受 policy 参数，换 `--policy` 不改 `direction`。
- `DiffResult` 是 `list` 子类，额外携带本次比较的两份 IR：`judge` 在 `*-transitive` 档据此对每个
  历史版本重算 `diff`（也接受已算好的差异列表）。缺 `--history` 的拒绝由 `resolve_policy` 做，
  `judge` 不重复判一次（避免两处口径漂移）。
- `judge` 把方向 × policy 映射成 `compatible|breaking`：`backward*` 接受 `BACKWARD_OK|BOTH_OK`，
  `forward*` 接受 `FORWARD_OK|BOTH_OK`，`full*` 只接受 `BOTH_OK`；`none` 恒 `compatible`。
- `--emit-policy` 是**数据导出**出口（与 `--emit-ir` 同构）：`{inputs, format, differences,
  verdicts, history, notes, digest}`；退出码 0 只表示导出成功，不表示兼容。
- **方向语义**（`data/README` §4.1）：`BACKWARD_OK` = 新写老读通；`FORWARD_OK` = 老写新读通。
  "删字段"：新数据缺字段 → backward 不可读、forward 可读 → `FORWARD_OK`（三格式一致）。

**测试点**：`test_policy.py` —— 七档各一条用例；同一"删字段"三格式 direction 一致；
`--policy=none` 全差异但 verdict=compatible；transitive 缺 history → exit 2；
`--explain-mapping` 四行齐且含"不宣称等价"；判 verdict 不受文件名/字段声明顺序影响。

## 7. rules.py + rules/rule-table.json

规则表形态（**数据不是代码**）：

```json
{
  "schema_version": 1,
  "rules": [
    {"rule_id": "R1", "name": "FIELD_REMOVED", "default_severity": "breaking",
     "formats": {
       "proto":      {"evidence": "field_number_missing_without_reserved", "applies": true},
       "avro":       {"evidence": "field_absent_or_renamed_without_alias", "applies": true},
       "jsonschema": {"evidence": "property_absent_or_removed_from_required", "applies": true}
     },
     "repair_action": "reserve"}
  ]
}
```

- `applies=false` → 输出 `format_evidence: "N/A"` + 一行理由，**不得省略该行**（R5/R6 的 Avro/JSON Schema）。
- `severity` 三值；`runtime-dependent` 必须带 `why_static_breaking` + `what_would_trigger`
  （文本模板在规则表里，逐规则可改，不在代码里拼 if）。
- **命中顺序**：按 `(rule_id, stable_path)` 排序。

**测试点**：`test_rules.py` —— 遍历规则表断言 7 条 × 3 格式槽位齐（结构性，防漏规则）；
每条规则至少一条命中用例；`N/A` 用例断言该行存在且有理由；`runtime-dependent` 三断言
（条目在、两段说明在、严格档 exit 1）。

## 8. blast.py

```python
def attribute(findings, deploy_order) -> list[Finding]   # 填 blast_radius / repair_action
```

- 输入 `(direction, deploy_order, 字段可寻址性)` 三元组，输出 `blast_radius` 四态。
- **不给 `--deploy-order` → `blast_radius = null` + `notes` 含 `deploy_order_not_given`**，不猜。
- `REPLAY_ONLY` 只在 `replay` 下出现。
- `repair_action` 的描述文本按格式给**可执行落点**（`reserved 4;` / `"aliases": [...]` / `"default": ...`）。

**测试点**：`test_blast.py` —— 同一破例四种发布顺序各断言一次（4×N 个断言，不是一条）；
缺 deploy-order 时 null + note；`runtime-dependent` 条目不被压平。

## 9. report.py

```python
def to_json(report) -> dict          # 规范形态
def to_markdown(report) -> str       # 渲染视图
def verify(path, expected_digest) -> int   # 0 一致 / 2 异常输入 / 1 篡改
```

规范 JSON 顶层键（固定序）：

```text
tool, version, policy, inputs{old,new}, ir_unsupported[], findings[], summary, notes[], digest
```

- `inputs` 只写**格式 + 用户给的 basename**（不写绝对路径）——`basename` 也必须脱敏（见 §4.7）。
- `findings[*]` 固定键序：`rule_id, rule_name, stable_path, severity, format_evidence, direction,
  blast_radius, repair_action, repair_hint, evidence, why_static_breaking, what_would_trigger`。
  不适用的字段**保留键**并写 `null`（键序稳定比"省略键"更重要）。
- Markdown 与 JSON **同源**：md 由同一份 report 对象渲染；改一个结论字段 md 必须变（测试断言）。
- **md 不参与 digest**：`digest` 只对 JSON 字节算。

**测试点**：`test_report.py` —— 键序固定（比对 golden 的 key 顺序）；两次渲染逐字节一致；
md 不含绝对路径；`--verify` 改一字节 → 退出码非 0 且 `json_path` 指向被改字段。

## 10. cli.py（参数面与退出码）

```text
compat <old> <new> [--policy {backward,backward-transitive,forward,forward-transitive,full,full-transitive,none}]
                   [--format {md,json}] [--deploy-order {consumers-first,producers-first,simultaneous,replay}]
                   [--history PATH ...] [--explain-mapping] [--require-complete-ir]
                   [--emit-ir | --emit-policy]
                   [--strict-runtime-dependent | --ignore-runtime-dependent]
                   [--verify PATH] [--version]
```

- 参数面是**验收面**：README 里每条命令都要能被 `parser.parse_args()` 解析（反射对账门，M6）。
- `--emit-ir` 与 `--emit-policy` 是**数据导出**模式（互斥）：退出码 0 只表示导出成功，不表示兼容；
  `--emit-policy` 是 policy golden 的唯一入口。
- 退出码异常分类见 `plan/02` §五。`argparse` 的 `SystemExit(2)` 在 `main()` 里捕获并统一返回 2。
- **`--format=md` 是默认**；未知格式由其 `choices` 拒绝（exit 2）。
- **`--strict-runtime-dependent` 默认开**：`--ignore-runtime-dependent` 是唯一关闭方式；
  二者同时给 → exit 2（矛盾参数不猜）。

**测试点**：`test_cli.py` —— 每条 flag 各一条解析用例；`--version` 输出含版本；未知 policy → 2；
缺 `--history` 的 transitive → 2；`--verify` 与 `--format` 互斥冲突 → 2；`compat --help` 退出 0。

## 11. 失败路径总表

| 触发 | 异常 | 退出码 | 是否写产物 |
|---|---|---|---|
| 文件不存在 | `UsageError` | 2 | 否 |
| 非法 JSON / 非法描述符 | `SchemaParseError` | 2 | 否 |
| 未知 policy / 未知 format | argparse | 2 | 否 |
| transitive 缺 `--history` | `UsageError` | 2 | 否 |
| 互相矛盾的 flag | `UsageError` | 2 | 否 |
| 无 `protoc`（`.proto` 输入） | `CapabilityError` | 3 | 否 |
| 无 `protobuf`（`.pb` 输入） | `CapabilityError` | 3 | 否 |
| `--require-complete-ir` 且 `ir_unsupported` 非空 | `CapabilityError` | 3 | 否 |
| 有 breaking | `Verdict` | 1 | 是（报告照出） |
| `--verify` 内容不一致 | `Verdict` | 1 | 否（只打印定位） |

**失败路径零副作用**：拒收时一个字节都不写；`--verify` 不覆盖被校验文件（测试断言前后 sha256 相同）。
