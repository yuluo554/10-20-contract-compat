> 本文件规划数据形态、覆盖度与真值纪律；**数值口径（七档/规则/退出码/归因）唯一定义在 `data/README.md` §四**，
> 本文档只描述"数据怎么造、怎么冻、怎么对账"。

## 二、fixture 设计（覆盖矩阵）

7 条规则 × 3 格式 = 21 对 `old/new`，每对只演一件事（**最小 schema**：1–3 个字段）。

| rule | proto fixture | avro fixture | jsonschema fixture |
|---|---|---|---|
| R1 `FIELD_REMOVED` | 删字段号且未 reserved | 删字段 | 删 property |
| R2 `TYPE_CHANGED` | `int32 → string`（非 wire 兼容） | `int → string` | `type: integer → string` |
| R3 `REQUIREDNESS_CHANGED` | `optional → required`、加无默认字段 | 加字段无 `default` | 加进 `required` |
| R4 `ENUM_NARROWED` | enum 删值 / 改名 | `symbols` 删 | `enum` 收窄 |
| R5 `FIELD_NUMBER_REUSED` | ① 跨 message 同号 ② 与 reserved 冲突 | `N/A`（显式） | `N/A`（显式） |
| R6 `ONEOF_MOVED` | 字段进出 oneof | `N/A` | `oneOf` 分支移动 |
| R7 `DEFAULT_CHANGED` | `default_value` 变 | `default` 变 | `default` 变 |

**三个"同一语义"夹具**（红线①的可机械检查面）：`removed-field-{old,new}` 必须在三格式各一份，
且 `test_policy.py` 断言三者 direction 完全相同。

**反例（至少 4 条）**：

| 反例 | 期望 |
|---|---|
| Avro union 新增一个类型 | `non-breaking`（resolving decoder 可读） |
| Avro 改名 + 声明 `aliases` | `non-breaking` |
| Protobuf 删字段但号已 `reserved` | `non-breaking`（R1 不命中；R5 也不命中） |
| JSON Schema 加可选 property（不进 `required`） | `non-breaking` |

反例的作用是**防止规则退化成"看到变化就报破"**——没有反例，误报率无门可守。

## 四、真值纪律

1. **真值只存"输入与期望"**：golden 里出现 `observed_*` 一类字段即视为违规（冻结观测 = 比对两份预先
   算好的答案，引擎全坏也全绿）。
2. **golden 由生成脚本产出并入库**；测试**只读 golden 比对**，不在测试里重算期望值。
3. **golden 生成器与生产实现分离**：`data/tools/gen_golden.py` 只允许调用 CLI（生产实现），
   **不得自己实现判定逻辑**——否则"两份实现同错"。
4. **双跑逐字节**：`--check` 模式重生成到临时目录 → 与入库 golden 逐字节比对（守门两层：
   验冻结产物形态 + 验重生成结果）。
5. **反例必须被 golden 覆盖**，且 `test_negatives.py` 断言"反例的 findings 为空或全 non-breaking"。

**"期望值可由输入独立复算"的落法**（本项目形态）：每条 golden 的期望值 = 人工核对过的
`(rule_id, severity, direction, blast_radius)` 四元组，写在 `data/golden/README.md` 的表里；
测试把 golden JSON 与这张表**双向对账**（表里没有的 golden、golden 里没有的表项都红）。

## 五、覆盖度口径

- **登记"规则包总数 / 已覆盖数"**：7 条规则 × 3 格式 = 21 格；`data/golden/README.md` 的矩阵表
  逐格打勾。`test_rules.py` 遍历规则表断言 21 格全覆盖（**穷举**，不是抽样）。
- **N/A 也算覆盖**：R5/R6 在 Avro/JSON Schema 下的 `N/A` 是**结论**，不是缺格——矩阵表里标 `N/A` 并给理由。
- **反例单列计数**：`negatives=4/4`。
- **不可表达构造单列计数**：`ir_unsupported=4/4`。
- 覆盖度数字**由脚本计算并打印**（`tests/test_coverage.py` 直接断言并打印矩阵），不手填。

## 六、合成数据纪律（引用 `data/README.md` §三）

- 全部自建最小 schema，字段名用中性占位（`order_id` / `total_amount` / `status`）。
- 不含真实公司/产品/人员/内部字段名；示例值只用保留值（`19900000000` 段、`example.invalid`）。
- **不引用任何真实生产 schema**——没有可复算、许可清晰的跨格式语料（`data/README.md` §二 已登记阻断原因）。

## 七、数据冻结与 EOL

- `.gitattributes`：`* text=auto eol=lf`；`*.pb binary`；golden 文本若被 sha256 登记则 `-text`。
- **fixture 是交付物，必须入仓**（`.gitignore` 已声明 `report-out/` 临时产物不入仓）。
- 生成器若存在：`gen_fixtures.py --check` 必须位级一致；**部分运行（`--only`）不得改写全集清单**。
- `*.pb` 是**程序化构造后入仓**的（2026-10-20 定案，见 §八）——用户不需要装 protoc 就能跑
  Avro / JSON Schema 场景，也能跑"已提供描述符"的 Protobuf 场景；只有"从 `.proto` 文本开始"
  才需要 protoc（exit 3 路径）。
- 每个 `.pb` 的 `.proto` 同源文本与描述符**由同一个 spec 渲染**（`data/tools/gen_fixtures.py`），
  不会出现"文本说的是 A、二进制说的是 B"。

## 八、数据依赖的环境事实（2026-10-20 实测，已处置）

| 事实 | 影响 | 处置（已执行） |
|---|---|---|
| 本机**无 `protoc`** | 无法用 protoc 生成 `.pb` | **改用 `protobuf` 库程序化构造 `FileDescriptorSet`**：生成器入仓（`data/tools/gen_fixtures.py`），`--check` 位级复现，CI 不装 protoc 也能跑全量 fixture |
| 本机原本**无 `protobuf` 包** | 解析器无法运行 | 已装：`py -3.12` → protobuf **7.36.2**，`py -3.8` → protobuf **5.29.6**。两档解释器产出的描述符字节**逐字节相同**（实测 sha256 一致），这是"跨解释器可复算"的直接证据 |
| `.pb` 字节随 protobuf 版本变动 | 大版本升级可能改序列化 | `gen_fixtures.py --check` 是守门：字节一变就红，**不会静默漂移**；要升级 protobuf 必须同轮重生成 fixture 并说明 |
| Python 3.8 无 `typing` 新语法 | 不能用 `list[str]` 注解 | 统一用 `typing` 别名 / 不写新式注解；两档解释器全量测试均需绿 |
| 描述符**不必含 NUL 字节** | "NUL 才算二进制"会把合法 `.pb` 判成 proto 文本 | `detect_format` 改为**往返校验**：能 `ParseFromString` 且重新序列化逐字节相同才认（`parsers/__init__.py:looks_like_descriptor_set`） |

> **M1 决策点（已定案 2026-10-20）**：`.pb` 用 `protobuf` 库**程序化构造**，不用 `protoc` 生成。
> 理由：生成器可入仓、`--check` 可位级复现、CI 不装 protoc 也能跑全量 fixture。
> `--require-complete-ir` 与"`.proto` 文本输入"两条路径仍是 exit 3（不需要 protoc 在场也能验）。
