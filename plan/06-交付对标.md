## 四、风险登记

| # | 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|---|
| K-1 | 三格式语义无法完全对齐，硬凑导致误判 | 中 | 高（红线③） | 允许 `N/A`；反例锁误报 |
| K-2 | IR 表达力不足导致静默忽略（getsentry 的坑） | 中 | 高 | `ir_unsupported` 必须非空 + `--require-complete-ir` |
| K-3 | 规则散落在代码里 → "每条规则都有用例"不可机械核对 | 中 | 中 | 规则表是数据；测试遍历表 |
| K-4 | 报告含时间戳/路径 → digest 不可复算 | 低 | 高 | 字段白名单 + 报告扫描断言 |
| K-5 | 归因硬编码单一结论 → 与 `--deploy-order` 无关 | 中 | 高 | 四种顺序各断言一次（不是一条参数化） |
| K-6 | 默认 `deploy-order` 被当成结论 | 中 | 高 | 缺省即 `null` + note |
| K-7 | 发布期"文档点名的门没有实物" | 中 | 中 | 布局门 `DOC_TOOLS` 判据（文档点名的 tools 必须在位） |
| K-8 | 版本号多处手改漏一处 | 中 | 低 | 单一版本源 + dynamic version |
| K-9 | CI 首推因 YAML 纯量含 `: ` 而 0 job | 低 | 中 | 本地 `yaml.safe_load` + 断言 job/step 数 |

## 五、决策记录（增量；主表在 `plan/00`）

| 日期 | 决策 | 理由 |
|---|---|---|
| 2026-10-20 | 布局门用 **Python** 实现（`tools/check-sprint-layout.py`），不用 Node | 项目是 Python 项目，CI 与本地都不必额外装 Node；判据集与模板一致（**判据不改，只换语言**） |
| 2026-10-20 | `protobuf` 只作为**可选运行时依赖**（`[project.optional-dependencies] proto`），不进核心依赖 | 核心判定路径（Avro/JSON Schema/判定/报告）零第三方依赖；只有 `.pb` 输入才需要。若放在核心依赖里，会把"零依赖 CLI"的卖点削弱 |
| 2026-10-20 | 版本号单一源 = `src/contractcompat/__init__.py:__version__`，`pyproject` 用 dynamic | 避免两处手改漏一处（K-8） |
| 2026-10-20 | 报告 JSON 的 `inputs` 只写 basename，不写路径 | 报告要能跨机复算 digest（`data/README` §4.7） |
