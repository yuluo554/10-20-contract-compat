# 02 · 架构与技术选型

> 口径引用纪律：七档 policy / buf 四档映射 / 七类规则 / `runtime-dependent` 条件 / 退出码矩阵 / 归因四态
> **一律只引用 `data/README.md` §四**，本文档不复述第二份定义，只描述"它们如何被装配"。

## 一、分层

```text
┌──────────────────────────────────────────────────────────────┐
│ cli.py           参数面 / 退出码 / 一条命令出结果              │
├──────────────────────────────────────────────────────────────┤
│ report.py        规范 JSON（唯一机读形态） + Markdown 渲染视图  │
│                  digest = sha256(规范 JSON 字节)              │
├───────────────────────┬──────────────────────────────────────┤
│ blast.py 归因 + 修复   │ rules.py 规则表命中（数据驱动）        │
├───────────────────────┴──────────────────────────────────────┤
│ policy.py        方向性判定核（七档 × 差异项 direction）        │
├──────────────────────────────────────────────────────────────┤
│ ir.py            ContractIR（三格式同构）+ 规范序 + ir_unsupported │
├──────────────────────────────────────────────────────────────┤
│ parsers/         proto.py / avro.py / jsonschema.py           │
│                  （各自独立，只依赖标准库 + protobuf）          │
├──────────────────────────────────────────────────────────────┤
│ canonical.py     规范 JSON 序列化 / 排序 / digest / --verify    │
└──────────────────────────────────────────────────────────────┘
```

数据流（单次命令）：

```text
old 文件 ─┐
          ├─► parsers ─► ContractIR(old) ─┐
new 文件 ─┘                               ├─► policy.diff ─► findings(差异项)
history  ─┘（可选）                        ┘        │
                                                    ├─► rules 命中（rule_id/severity/证据）
                                                    ├─► blast 归因（deploy_order 决定）
                                                    └─► report（规范 JSON → md 视图）
```

**分层硬约束**

| 约束 | 判据 | 落法 |
|---|---|---|
| 解析层不判定 | `parsers/*` 不得 import `policy`/`rules`/`blast` | AST 守门测试（禁止 import 名单） |
| 判定层不渲染 | `policy.py`/`rules.py` 不得 import `report` | 同上 |
| 渲染层零判定 | `report.py` 只读传进来的结论，不做任何比较 | 渲染测试：同一结论对象渲染两次逐字节一致；改一个结论字段必变 |
| 规则表是数据 | `rules.py` 只加载 `rules/rule-table.json` 并求值，命中条件不写成散落 if | 测试遍历规则表断言 7 条 × 3 格式槽位齐 |
| 单点序列化 | 所有 JSON 落盘/输出走 `canonical.dumps` | 全仓 `json.dumps(` 只允许出现在 `canonical.py`（AST/文本守门） |

**为什么解析器独立**：三种格式的"读法"没有任何共享语义——Protobuf 读 `FileDescriptorProto`、Avro 读
`fields/default/aliases/symbols`、JSON Schema 读 `properties/required/type/enum/oneOf/$ref`。它们唯一的
共同点是**输出同一个 `ContractIR`**。把共享点放在 IR，而不是放在"通用 JSON 遍历"，才谈得上"归一"。

## 二、ContractIR（同构中间表示）

`ir.py` 定义纯数据对象（可用 `dataclasses`，3.8 可用），序列化为规范 JSON：

```json
{
  "format": "proto | avro | jsonschema",
  "name": "<消息/记录/schema 标题，缺失时为空串>",
  "fields": [
    {
      "name": "order_id",
      "number": 1,                    // Protobuf/Avro 字段位置；JSON Schema 为 null
      "json_pointer": "/properties/order_id",
      "type": "string",
      "cardinality": "required | optional | repeated | nullable",
      "default": {"present": false, "value": null},
      "enum_values": [{"name": "PAID", "number": 2}],
      "oneof_membership": null,
      "aliases": [],
      "reserved": false
    }
  ],
  "reserved_numbers": [3, 4],
  "reserved_names": ["legacy_field"],
  "ir_unsupported": [
    {"construct": "patternProperties", "json_pointer": "/patternProperties", "reason": "正则键无法枚举为固定字段集"}
  ]
}
```

**规范序**：`fields` 按 `(number 若存在, json_pointer, name)` 升序；缺失 `number` 的字段排在所有有号字段
之后（`(1, 0, json_pointer, name)` vs `(0, number, "", name)` 的二元键，**不比较 `None`**——Py3 下
`None < int` 会抛 `TypeError`，这是必然踩的坑）。`enum_values` 按 `(number, name)`；
`reserved_numbers` 去重升序；`ir_unsupported` 按 `(json_pointer, construct)`。

**`default` 三态**：`present=false`（无默认）/ `present=true, value=null`（显式 null）/ `present=true, value=X`。
用 `null` 兼表"无默认"会让"默认值被改成 null"和"删掉默认值"变成同一种东西——这正是 R7 要区分的。

**`ir_unsupported` 是输出，不是日志**：不可表达的构造一律进这个数组，`report` 必须把它渲染出来；
`--require-complete-ir` 时非空即退出码 3（见 `data/README.md` §4.5）。

## 三、判定核（policy.py）

- 输入：`ContractIR` 两份（+ 可选历史列表）+ policy 名字。
- 中间产物：`diff` 产生的**差异项**（不是结论），每项带 `direction` ∈ `{BACKWARD_OK, FORWARD_OK,
  BOTH_OK, NONE_OK}`。**方向是事实，policy 是选择**——同一份 diff 换 policy 不改 direction。
- 输出：`verdict` ∈ `{compatible, breaking}` + 差异项清单。
- `policy=full` = backward ∧ forward；`*-transitive` = 对历史序列逐版本求同一判据；
  `policy=none` 恒 `compatible`。
- **transitive 缺 `--history` 必须退出码 2**，不降级（降级会把"与历史不兼容"静默报成兼容）。

`--explain-mapping` 的映射表是**常量表**（`data/README.md` §4.2 的代码侧唯一副本），逐行带"关系说明"，
且整表必须含"只表达最接近、不宣称等价"字样（测试逐行断言）。

## 四、确定性架构

| 风险源 | 处置 | 守门 |
|---|---|---|
| dict/set 迭代序 | 所有落盘结构用显式排序键；禁 `set` 直接迭代 | 双跑逐字节比对 |
| 时钟 | 报告零时间字段；解析层不读 `time` | AST 守门：`report.py`/`ir.py` 禁 import `time`/`datetime` |
| 路径 | 报告不写绝对路径；错误信息只写用户给的相对位置 | 报告字段扫描：无 `\` + 盘符形态、无 `/home/` |
| 主机/用户 | 不读 `getpass`/`socket.gethostname`/`platform.node` | AST 守门（`canonical.py` 例外为零） |
| 浮点 | 本工具不做数值计算，只比较 `default` 字面量与类型名 | 无需定点化；`default` 原样保留 JSON 值 |
| 哈希 | `digest = sha256(规范化 JSON 字节)`，不含 digest 自身 | `--verify` 重算 |
| Markdown | 只是 JSON 的渲染视图，**不参与 digest** | 测试：同数据二次渲染逐字节一致 |

**abspath 纪律**：CLI 允许读任意路径（用户给的），但**任何路径不得进入报告**；`--verify` 的定位信息
只给 `json_path`（如 `findings[3].severity`），不给源文件路径。

## 五、退出码契约（装配层）

`data/README.md` §4.5 是唯一定义处。装配层的职责是**把异常类型映射到码**：

```text
UsageError        -> 2   （未知 policy / transitive 缺 history / 文件不存在 / JSON 非法 / 描述符非法）
CapabilityError   -> 3   （无 protoc / 解析器不可用 / --require-complete-ir 且 ir_unsupported 非空）
Verdict(breaking) -> 1
Verdict(ok)       -> 0
```

**自定义异常必须显式分类**，不允许 `except Exception: return 2`——那会把"环境给不了"混成"你写错了"，
正是发布门要区分的那件事。

## 六、技术选型

| 项 | 选择 | 理由 / 弃选 |
|---|---|---|
| 语言 | Python 3.8+ | 本机两档解释器（3.8.8 / 3.12.10）都能跑；不依赖 3.9+ 语法 |
| 运行时依赖 | `protobuf`（仅 `google.protobuf.descriptor_pb2`） | 唯一第三方依赖；无则 Protobuf 输入退出码 3 |
| 测试 | `pytest`（dev extra） | 本机两解释器均已有 |
| 打包 | `setuptools` + `pyproject.toml`（`[project.scripts] compat`） | 不走 poetry/hatch，减少构建面 |
| `.proto` 输入 | **不解析文本**，必须 `protoc --descriptor_set_out` | 自写解析器 = 首期最大伪工作量（题面 §六） |
| 配置 | 无配置文件、无环境变量 | 口径随包走，CLI 参数即全部输入 |
| 网络 | 零网络 | 隐私红线；测试里禁 `socket` |
| LLM | 不使用 | 判定必须可复算 |

**"零依赖"的边界**：核心判定路径（Avro / JSON Schema / 判定 / 报告）**不依赖 protobuf**；只有
`.pb`（`FileDescriptorSet`）输入才 import 它。因此 `protobuf` 缺失时其余两种格式照常工作——
这条要在测试里用 import 桩验（不靠"本机装没装"）。

## 七、构建与安装

```bash
py -3.12 -m venv .venv
./.venv/Scripts/python.exe -m pip install -e ".[dev]"     # Git Bash
compat --version
```

- **单一版本源**：`src/contractcompat/__init__.py` 的 `__version__`；`pyproject.toml` 用
  `dynamic = ["version"]` + `[tool.setuptools.dynamic] version = {attr = "contractcompat.__version__"}`，
  避免"两处手改漏一处"。
- **版本四处一致**（M6 由测试断言）：`__version__` / 已安装元数据 / `README.md` 顶部 / tag 名。
- **构建确定性**：源码包用 `git archive <tag>` + `gzip -9n`（不用 `python -m build` 的 sdist 作为附件，
  避免 `PKG-INFO` 与时间戳进入发布件）。`[tool.setuptools.packages.find] where = ["src"]`。
- **数据不入包**：`data/`（fixture/golden）不进 wheel；源码包含 `data/` 与 `rules/`（`MANIFEST.in` 白名单，
  M6 验证"解包 → 装 → 从解包目录之外跑"）。
- **CI**：`.github/workflows/ci.yml`，矩阵 `ubuntu-latest × 3.12`、`windows-latest × 3.8/3.12`；
  步骤固定为 布局门 → pytest → 裸 `compat --version` 冒烟（裸命令与 `python -m` 是两条通路）。

**弃选**：PyInstaller/exe（题面要求可安装 CLI，exe 会把发布面翻倍）；Docker 镜像（零部署是卖点）；
服务端形态（题面 §六 明确不做）。
